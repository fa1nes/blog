## 写一篇新文章

在 `src/content/posts/` 下新建一个 `.md` 或 `.mdx` 文件，文件名就是文章的网址。比如 `my-first-post.md` 会生成 `/posts/my-first-post/`。

每篇文章的开头是一段被称为 frontmatter 的元信息：

```yaml
---
title: 文章标题
description: 一句话摘要，会用在列表、搜索和分享卡片上
pubDate: 2026-07-20
category: 技术
tags: [性能, 前端]
---
```

只有 `title` 和 `pubDate` 是必填的。其余字段都有合理的默认值：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `description` | 字符串 | 自动截取正文 | 摘要，留空时从正文开头提取 |
| `category` | 字符串 | `未分类` | 一篇文章只属于一个分类 |
| `tags` | 数组 | `[]` | 标签可以有多个 |
| `slug` | 字符串 | 文件名 | 想自定义网址时使用 |
| `draft` | 布尔 | `false` | 草稿只在本地可见，不会被构建 |
| `pinned` | 布尔 | `false` | 置顶到列表最前面 |
| `toc` | 布尔 | `true` | 单篇关闭目录 |
| `comments` | 布尔 | `true` | 单篇关闭评论 |

写作时执行 `npm run dev`，保存文件浏览器会立即刷新。想暂时藏起某篇稿子，把 `draft` 设成 `true` 就行，它在本地依然可见，但不会出现在正式构建里。

## 改配置

几乎所有需要改的东西都集中在 `src/site.config.ts` 一个文件里：站点标题、作者信息、导航菜单、社交链接、每页文章数、评论开关、页脚备案号。

```ts
export const site = {
  url: 'https://example.com',
  title: '砚台与代码',
  subtitle: '记录构建、阅读与思考的地方',
  // ...
};
```

改完保存即可，不需要动任何组件代码。

> 唯一需要留意的是 `site.url`。它决定了 RSS、sitemap 和分享卡片里的绝对链接，部署前记得换成你自己的域名。

## 关于性能的几个取舍

这套主题的默认立场是：**能在构建时做完的事，就不要留到浏览器里做**。

- **没有前端框架**。页面是纯 HTML 加 CSS，没有 React、Vue 这类运行时。
- **JavaScript 按需加载**。深色模式切换、代码复制、目录高亮各自只有几十行，且只出现在真正需要的页面上。搜索的脚本只在 `/search/` 页面加载。
- **移动端菜单不用 JavaScript**。它是一个原生的 `<details>` 元素，展开收起由浏览器负责。
- **字体不联网**。全部使用系统字体栈，省掉了几百 KB 的字体文件和一次跨域请求。
- **搜索索引在构建时生成**。Pagefind 会把索引切成小块，搜索时只下载用得上的那几片，而不是把全站内容打包进 JavaScript。

代价是有一些花哨效果做不了，比如页面间的平滑过渡动画。这是刻意的选择：阅读文字的时候，动画通常只会分散注意力。
